# 动量趋势+做T 止损体系重构设计方案（推倒重来）

> 关联任务：`bt_84f3d9c10301`（300万5分钟动量轮换6槽位单股20%限仓）
> 策略：`momentum_slot` · 周期 `minute5` · 动态选股 + 池级趋势开关开
> 状态：**设计草案（未实现）** · 日期：2026-09-04
> 前置：`STOP_LOSS_EXIT_OPTIMIZATION.md`（已落地确认期 + 去持续性，A/B 验证有效）

---

## 0. 背景：为什么需要推倒重来

动量趋势+做T 的收益结构 = **趋势段吃主升浪（趋势跟踪肥尾）+ 震荡段做T波动变现**。
当前止损体系是"两个独立模块 + 一个仓位"，存在三个结构性矛盾（补丁式优化无法根治）：

| 冲突 | 机制 | 后果 |
|---|---|---|
| 锁盈 vs 卖飞 | 移动止损要锁盈（收紧），做T要高抛低吸（需波动） | 同一仓位上两套逻辑互相拉扯 |
| 趋势止损 vs 震荡扫损 | 震荡市趋势型止损反复假破位 | 震荡市（做T主场）被止损反复误杀 |
| 个股止损 vs 槽位轮动 | 6槽位靠轮动补位，止损却是"个股价格触发" | 与组合相对强弱脱节，退出资金不自动进强者 |

**核心判断**：止损与做T本质是同一件事的两面——都在管理「仓位 vs 价格」的关系。
重构方向 = 统一为**状态驱动的双层仓位管理**，叠加市场状态开关与组合层轮动。

---

## 1. 目标架构（总览）

```
市场状态判定（趋势市/震荡市）                    ← 方向 A
        │
        ▼
持仓分两层（同一股票，两个 group）                ← 方向 B
├─ 核心仓（趋势仓）：动量状态机退出 + 宽松趋势止损   ← 方向 D
└─ 交易仓（做T仓）：波动止损 + 单笔底线 + 网格      ← 方向 B
        │
        ▼
组合层：排名驱动的槽位轮动 + 回撤熔断联动           ← 方向 C
```

四方向可叠加，改动相互独立，每一步可单独 A/B 验证。

## 2. 方向 A：市场状态双模（趋势市 / 震荡市）

### 2.1 目标
解决「趋势止损 vs 震荡扫损」：在震荡市止损哲学改为"快进快出 + 高做T"，在趋势市保持"宽松趋势止损 + 低做T（防卖飞）"。

### 2.2 详细设计
- **市场状态判定**（日级，市场层而非个股层）：
  - 候选：沪深300/中证500 指数 20 日均线方向（`idx_ma20_slope`）、全市场 ATR 分位（`vol_regime`）、市场广度（上涨家数占比 `breadth`）。
  - 输出一个状态列 `market_regime ∈ {trend, range}`（二态起步，可选 `crash` 第三态）。
- **状态驱动**：
  - `trend`：核心仓权重 ≥ 默认、`exit_confirm_days` 确认期生效（给反弹窗口）、做T频率系数 `t_regime_scale=0.5`（防卖飞）、`atr_trail_mult`（移动锁盈倍数）放宽。
  - `range`：核心仓收缩（`core_weight_scale=0.6`）、`exit_confirm_days` 关或缩短（快进快出）、做T频率 `t_regime_scale=1.3`（波动变现）、止损收紧（`atr_trail_mult`×0.8）。
- **新增参数**：`market_regime_on`（市场状态开关，0=关沿用现状）、`regime_ma_days`（市场状态均线周期，默认20）、`t_regime_scale`（震荡市做T频率系数，默认1.0）、`core_weight_scale`（震荡市核心仓权重系数，默认1.0）。

### 2.3 与现有引擎对接
- **状态来源（注入点）**：仿照 `pool_gate` 的注入方式——`pool_gate` 由 `momentum_slot.prepare()` 预计算并注入每只股票 df 的 `pool_gate` 列。市场状态同理，在 `prepare()` 或 runner 数据准备阶段算好 `market_regime` 列（同一列复制到所有股票，引擎逐 bar 可读）。
  - 涉及文件：`momentum_slot.py::prepare`（或新增 helper 注入）、`runner.py::_simulate`（读取 regime 列传入策略步进）。
- **消费点（策略层）**：`SlotStepper.step()` 增加 `regime` 入参；建仓预算 × `core_weight_scale`、做T触发频率 × `t_regime_scale`、确认期参数按 regime 切换。
- **消费点（引擎层）**：`runner.py` 做T频率限制 `_trades_today` 上限可按 `t_regime_scale` 动态缩放。
- **改动范围**：策略层 `momentum_slot.py`（schema + prepare + step）+ `runner.py`（传参/做T频率）+ 新增市场状态计算模块。风险：市场状态判定本身需要标定（A/B 验证）。

## 3. 方向 B：双层仓位（核心仓 / 交易仓）——最根本

### 3.1 目标
把「止损」与「做T」在**仓位层面**隔离：核心仓吃趋势、交易仓做波动，各自配止损，消灭"锁盈 vs 卖飞"与"多 group 退出不同步"。

### 3.2 详细设计
- **仓位分两层**（同一股票、两个 `group_id`）：
  - **核心仓（趋势仓）**：由建仓/加仓信号建立（tag=`开仓`/`加仓`），目标是趋势段收益。止损 = **趋势止损**（动量状态机退出为主 + 宽松 ATR 移动线兜底）。
  - **交易仓（做T仓）**：由做T信号建立（tag=`做T`），目标是波动段收益。止损 = **波动止损**（单笔做T成本底线 + 紧 ATR 线），与核心仓完全隔离。
- **引擎现状已天然支持**：`Portfolio.add_position` 对开仓/做T 自动分配不同 `group_id`；`check_stops` 与 `pending_stops` 均按 `only_group` 隔离平仓（runner.py L1062-1085）。**双层仓位无需改动仓位层**，只需在**止损参数层**区分 group 类型。
- **止损参数分层**（核心改动）：
  - `RiskManager.check_stop` 目前对所有 group 用同一 `risk_cfg`。改为：按 `pos.group_id` 对应的 group 类型（`pos.kind ∈ {core, trade}`，开仓=core、做T=trade）取**不同止损档**。
  - 核心仓档：`core_k1/core_k2`（如 2.5/6，宽松趋势档）——当前参数。
  - 交易仓档：`trade_k1/trade_k2`（如 3.0/2.5，紧波动档）+ `trade_stop_pct`（单笔做T成本底线，如 -3%）。
- **新增参数**：`trade_tier_on`（双层止损开关，0=关沿用现状）、`trade_atr_mult`（交易仓硬止损倍数 k1，默认3.0）、`trade_trail_mult`（交易仓移动倍数 k2，默认2.5）、`trade_stop_pct`（交易仓成本底线%，默认3）。
- **做T债务与双层的关系**：`t_state` 债务链（sold/bought）继续按 group 跟踪；交易仓清仓不影响核心仓持有；反之核心仓清仓后交易仓可独立网格。

### 3.3 与现有引擎对接
- **核心改动点**：`risk.py::RiskManager.check_stop` / `_check_atr_trailing`——按 `pos.kind` 分流止损档；`portfolio.py::add_position` 或 `Position` 增加 `kind` 字段（由买入 tag 决定：开仓/加仓=core，做T=trade）。
- **策略层**：`SlotStepper` 建仓/做T 信号 tag 已区分（`开仓`/`加仓` vs `做T`），无需大改；仅在确认期/做T 交互时明确"确认期只作用于核心仓"。
- **runner**：`check_stops` 传 `pos.kind` 给 risk；`execute_sell` 按 group 隔离（已有）。
- **改动范围**：`risk.py`（止损分流）+ `portfolio.py`（kind 字段）+ `runner.py`（传 kind）。这是四方向里对接最聚焦、收益最直接的一项。
- **风险**：交易仓用紧止损可能增加交易次数/手续费；需 A/B 验证净贡献。

## 4. 方向 C：排名驱动的槽位轮动（个股止损降级为兜底）

### 4.1 目标
解决「个股止损 vs 槽位轮动脱节」：6槽位策略的收益本质是轮动（退弱者、补强者），把退出的主驱动从"个股价格止损"改为"相对排名淘汰"，个股止损降级为极端兜底。

### 4.2 详细设计
- **淘汰规则**（替代/优先于衰退退出的主驱动）：
  - 持仓股连续 `slot_stale_days`（槽位老化天数，默认5）个交易日未创 `slot_high_window`（新高窗口，默认20）日新高，且当日相对排名跌出 `pool_n` 候选 → 强制淘汰（换入当前候选池最强未持仓股）。
  - 保留现有 `max_holdings`/`_enforce_slots` 槽位约束：淘汰释放槽位 → 下一交易日自动补位最强候选。
- **个股止损降级**：ATR 移动止损 / ATR 硬止损保留，但定位为**极端兜底**（黑天鹅、一字跌停等），不再作为主力退出。
- **新增参数**：`slot_rotation_on`（排名轮动开关，0=关沿用现状）、`slot_stale_days`（槽位老化天数，默认5）、`slot_high_window`（新高窗口，默认20）。

### 4.3 与现有引擎对接
- **排名数据**：候选池排名 `top_days` 已由 `rank_days` 生成（日级，T-1 语义）；新增"持仓股每日相对排名/是否新高"的列，注入 df（仿 `pool_gate`）。
- **策略层**：`SlotStepper` 增加"老化淘汰"分支（优先级在衰退退出之后、做T之前）：持仓 N 日未创新高且排名出榜 → 返回清仓信号（tag=`清仓`，reason=`槽位老化淘汰`），引擎按现有清仓路径执行。
- **补位**：淘汰后槽位空出，`_enforce_slots`/建仓逻辑自动补位（现有机制），无需新增。
- **改动范围**：`momentum_slot.py`（schema + step 老化分支 + 排名列注入）+ `runner.py` 少量（如需把淘汰也纳入 `exit_cooldown` 冷却判定）。风险：轮动频率需标定，避免过度换手（手续费）。
- **与方向 D 的关系**：D 提供"动量状态机"判断个股强弱，C 提供"相对排名"判断组合强弱，二者可合并为统一的退出打分。

## 5. 方向 D：动量状态机退出（改进信号质量）

### 5.1 目标
把"衰退 3 取 2"升级为显式的**动量状态机**，用动量变化率做退出主信号，替代"信号凑数"的脆弱逻辑（已证实 `s3 跌出榜单`为持续状态会锁死退出）。

### 5.2 详细设计
- **动量状态机**（个股级，基于 score/趋势斜率）：
  - `ACCEL`（加速，score 上行且斜率>0）→ 建仓/加仓、宽松止损；
  - `CRUISE`（匀速，score 高位横盘）→ 持有，止损正常；
  - `DECEL`（减速，score 从峰值回落 > `decay_pct`）→ 减仓（替代"首减"）；
  - `FADE`（衰竭，score<0 或破快均线）→ 清仓。
- **退出信号**：状态迁移 `DECEL→FADE` 或 `FADE` 持续 `exit_fade_days`（衰竭确认日，默认1）→ 清仓。状态机天然无"持续状态锁死"问题（迁移是事件，非状态位）。
- **与现有衰退信号的兼容**：`exit_need`/`partial_exit_pct` 语义保留（首减/二清），但触发条件从"3 信号凑数"改为"状态迁移 + 确认期"。
- **新增参数**：`momentum_fsm_on`（动量状态机开关，0=关沿用现状）、`exit_fade_days`（衰竭确认日，默认1）。

### 5.3 与现有引擎对接
- **纯策略层改动**：`momentum_slot.py`——`SlotStepper` 增加状态机字段（`mom_state`），在 `step()` 里替代当前的 `s1/s2/s3` 判定；`_walk` 与实盘共用同一 `step`，无需改引擎。
- **参数**：`param_schema` 加开关与确认参数（默认 0/关，不影响现状）。
- **改动范围**：仅 `momentum_slot.py`。风险：状态机阈值（`decay_pct`/斜率窗口）需标定；需保留"新死叉/破硬线立即清"的急跌出口（经验证确认期出口不可滥用，但状态机本身的 `DECEL→FADE` 快速迁移可替代）。

## 8. 风险与约束

- **参数面**：每个方向新增 2~4 个参数，需控制总参数膨胀，优先复用现有 `decay_pct`/`atr_*` 语义；frozen 参数不参与寻优搜索。
- **回测口径**：5 分钟周期下"次日"=下一根 5 分钟 bar，确认期/老化天数均按交易日计（沿用 `day_idx`）。
- **实盘同步**：`SlotStepper` 状态机是回测与实盘共用实现（`LIVE_SIGNAL_SYSTEM §3`），新增状态字段必须同步 `state()/restore()` 落库（含 `mom_state`/双层 kind 等），否则实盘跨日恢复丢失。
- **手续费敏感性**：方向 B（交易仓紧止损）与方向 C（更频繁轮动）会增加交易次数，A/B 必须看净贡献（`commission_total` 与 `total_pnl` 对比）。
- **无后视镜**：市场状态（A）、排名轮动（C）判定一律用 T-1 数据，与现有"选股基准日 = 严格早于段首最近交易日"约定一致。

## 9. 实测记录（2026-09-04，完整 A/B/D 演进）

方向 A（市场状态三态）/ B（双层止损）/ D（动量状态机）均按本章设计**完整实现并通过 A/B 验证**。结论：**仅 B 有效并已落地为默认参数（开关默认关）；A、D 证伪**。

### 9.1 结论总览

| 方案 | 实现 | A/B 结果（vs BASE 62.2%） | 判定 |
|---|---|---|---|
| **B 双层止损** | `trade_tier_on` + 做T仓独立止损档 | **tm=5/sp=10 → 82.4%，夏普 1.127，样本外 +24%** | ✅ **落地为默认参数**（开关默认关） |
| D 动量状态机 | `momentum_fsm_on`，三版演进（V1 盘中触发 / V2 fade-only / V3 decel→首减+fade EOD→二清） | V1 45.5% / V2 45.5% / V3 36.9%，全部劣于 BASE | ❌ 证伪 |
| A 市场状态三态 | `market_regime_on`，旧判定(MA20/60) 与 ADX 改进版(MA10/30+ADX) | 旧 46.3% / ADX 44.2%，全部劣于 BASE | ❌ 证伪（判定质量已改善但收益不变 → 结构性根因） |

### 9.2 B 的演进（关键：参数比方案重要）

- **B-默认（紧档 tm=2.5/sp=3）**：31.0%，T 仓止损 247 次——做T仓紧止损自残（波动低点被割、网格重复买回）。
- **B-宽档敏感度**：`tm=5/sp=10` → **82.4%**（+20pp），`tm=5/sp=8` → 63.4%，`tm=6/sp=8` → 61.2%。
- **落地默认**：`trade_stop_pct=10`（T 仓成本底线放 10% 给"等反弹"空间）+ `trade_trail_mult=5`（移动锁盈保留极端保护），开关 `trade_tier_on` 默认关。
- **时间因素验证**：B 的后段年化 **+23.6%**（BASE 为 -2.4%），样本外衰减显著收窄（degraded vs poor）——增益来自时间维度稳健性，非某段行情偶然。

### 9.3 A、D 证伪的根因认知

- **D**：状态机退出（无论 decel/fade 如何触发、是否 EOD 收盘确认）都让退出更"灵敏"，与"止损必须钝"矛盾。
- **A**：旧判定（MA20/60）滞后严重（2024-09 暴涨判 range），改进为 ADX+MA10/30 后判定质量明显改善（对照验证通过），**但收益几乎不变（46.3%→44.2%）**——证明 A 失败的根因是**结构性**的：收缩核心仓=减少做T底仓；市况缩放机制本身不产生正收益。

### 9.4 最核心的认知

这个 momentum+做T 策略的收益核心是**「持仓底仓 + 做T 波动变现」**：
- 任何**减少持仓**（A 核心仓收缩）、**减少操作**（A 做T降频）、**更早退出**（D 状态机）的机制都在自伤；
- B 之所以有效，恰因它**只给做T仓加保护、不减少任何操作**；
- 已落地的「确认期 + 去持续性」是"让退出更钝"（有效），A/D 是"更敏/更紧/更少"（证伪）。
