# 做T 机制重构方案（T\_REFACTOR）

> 状态：方案设计（待实现）
> 日期：2026-08-27
> 背景：23 个 momentum\_t 回测任务的全量实证表明 T 层**单笔期望 -7.86%、右尾失控（单笔最差 -27%）、83% 任务亏损**。病灶不是网格参数，是"卖出债务 + 无限追回"的机制设计。
> 关联：`MOMENTUM_T_AUDIT.md`（口径纪律）、`TREN_T_COMPARISON_PLAN.md`（实验矩阵基建，本方案复用）、`DYNAMIC_SELECT_PLAN.md`（策略融合）

***

## 1. 全量实证（决策依据）

样本：23 个含 ≥10 笔做T的 momentum\_t 回测任务（配对口径：同票做T卖出->后续做T买入的价差×量）。

| 指标            | 全局中位          | 范围          | 判读                           |
| ------------- | ------------- | ----------- | ---------------------------- |
| 胜率            | 35%           | 22%\~54%    | 低但非死因                        |
| **赔率（均盈/均亏）** | **0.23**      | 0.09\~1.32  | **死因：均盈 3.68% vs 均亏 14.04%** |
| 跨日占比          | **85%**       | 38%\~100%   | "做T"实为隔日波段+追高                |
| 中位敞口          | 23.2h         | 0.8h\~44.6h | --                           |
| **单笔期望**      | **-7.86%/笔**  | --          | 未计手续费 \~0.07% 往返             |
| T 盈亏为正的任务     | **4/23（17%）** | --          | --                           |

**右尾解剖（最差任务 -649 万）**：单票 300450 贡献 -545.9 万（84%）；最差 6 笔集中在 2025-08-29\~09-05 该票主升浪起点（价差 -18.9%/-27.3%/-22.5%）；存在 9/5 卖 -> **4 个月后**才买回的债务。**亏损=卖飞时点 × 追回无上限 × 债务无时限**。

**正面异常（正确方向的证据）**：唯一健康任务（胜率 54%/赔率 1.32/T 为正）的特征是**敞口 3.4h、跨日 46%**；敞口最短的三笔任务恰好赔率最好。亏损全部来自跨日敞口期间趋势继续走。

**报表口径问题（bug 级）**：现有 `t_pnl` 周期口径只算已闭环部分（未闭环债务浮亏不计入），与配对口径严重背离（某任务周期口径 -0.3 万 vs 配对 -186 万）--**当前报表系统性美化 T 层**。

## 2. 重构总纲

分三层递进，各自独立交付价值：

```
L1 纪律层（必做）：给现有机制装上双止损 + 报表诚实化
L2 机制层（主重构）：债务追回 -> 回补纪律（方案B）
L3 对照层：机制 A/B/C/D 竞争实验（复用 TREN_T 实验矩阵）
```

**设计原则**：

* 修右尾优先于提胜率（-27% 的单笔封到 -3% 比胜率 35%->45% 影响大一个数量级）

* 每层都可独立回滚（参数化开关，旧机制保留可对比）

* 新机制参数 ≤3 个（吸取 AUDIT OF3/OF4 的参数膨胀教训）

***

## 3. L1 纪律层：双止损 + 报表诚实化（1 天）

### 3.1 债务双止损（runner.py t\_state 机制改造）

```python
# 新参数（DEFAULTS + momentum_t param_schema 各 2 个）
"t_debt_max_days": 2,      # 时间止损：债务超过 N 交易日未回补 -> 作废转正式减仓
"t_max_chase_pct": 3.0,    # 价格止损：买回价 > 卖出均价 × (1+N%) -> 不追
```

**时间止损**（runner 主循环日界处检查）：

```
债务天数 > t_debt_max_days:
    该周期作废：债务清零（sold/bought/金额全归零）
    已卖出的量转为"正式减仓"语义（盈亏归 reduce_pnl 口径，reason="T债务超时转减仓"）
    底仓不足时由趋势层开仓信号自然回补（无强制）
```

**价格止损**（execute\_buy 做T债务买回分支）：

```
buy_price > st["sell_amt"]/st["sold"] × (1 + t_max_chase_pct/100):
    拒绝本次追回（同时间止损的作废处理）
    reason 记入 trade_log（"放弃追回：超 chasing 上限"），不成交
```

效果推演（用实证数据）：单笔均亏 14.04% -> 封顶约 3%+网格间距 ≈ 6%；-27% 笔消灭。期望值 -7.86% -> 约 **-1%\~+1%** 区间（能否转正待跑）。

### 3.2 报表诚实化（stats.py）

* `t_pnl` 改**配对口径**：做T卖出 -> 买回（或作废）实现/结算的价差合计，**未闭环债务按当前价浮亏计提**

* 旧周期口径保留为 `t_pnl_closed`（对照用）

* 新增 `t_win_rate`/`t_payoff`（配对口径胜率与赔率）进 metrics--这三项正是本实证的核心指标，让用户在报告页直接看到 T 层真实成色

* 回测结束时的未闭环债务在 report 里列明（code/卖出日/浮亏）

### 3.3 顺带参数修正（不动机制）

* `grid_atr_mult` 默认 0.5 -> **1.0**（间距=1×ATR，间距显著大于往返成本+日内噪声）

* `asym_bias` 语义增强：`bias > 2` 时禁止网格卖出（仅买回方向）--治强趋势卖飞

**L1 验收**：三案例 + 最差案例（bt\_cb3e96bcf383）复跑，配对口径 t\_pnl 期望值回到 -1%\~+1%；单笔最差价差绝对值 ≤ 6%；报表双口径可见。

## 4. L2 机制层：回补纪律替换债务追回（方案 B，2 天）

### 4.1 核心语义变更

```
旧机制：卖出后欠债 -> 价格触发买回 -> 无论多贵都要还（无限追）
新机制：卖出后挂"回补限价单" -> 只有价格回到 卖出价×(1-复购折让) 才回补
        -> 到期末回补 = 该笔视为一次成功的减仓（利润已落袋），债务自然消失
```

**数学结构对比**：

| <br /> | 旧（债务追回）       | 新（回补纪律）                |
| ------ | ------------- | ---------------------- |
| 单笔最好   | +网格间距         | +网格间距（同）               |
| 单笔最差   | **-无限（追高）**   | **0（不回补=减仓，卖出价已锁定利润）** |
| 敞口     | 无限（4 个月的案例实证） | ≤ t\_debt\_max\_days   |
| 与趋势层关系 | 对抗（追回=逆势买）    | **协同（不回补=顺势减仓）**       |

### 4.2 状态机改造（runner.py）

```python
# t_state: {sold, bought, sell_amt, buy_amt} -> {sold, bought, sell_px_avg, deadline_day, rebuy_limit}
# 网格卖出时：记录 sell_px_avg、deadline_day=当日+t_debt_max_days、
#            rebuy_limit = sell_px_avg × (1 - reentry_discount/100)
# 买回触发（策略信号"做T买回"照常产生）：
#   bar_price <= rebuy_limit: 正常回补（债务递减）
#   bar_price >  rebuy_limit: 拒绝，等待（不再是"无论多贵都买"）
# 到期检查（日界）：未回补部分 -> 债务消失（已实现利润保留在 reduce_pnl 语义）
```

新参数仅 2 个：

```python
"reentry_discount": 1.0,   # 回补限价折让（%）：卖出价下方 1% 才回补
"t_debt_max_days": 2,      # 复用 L1 的时限
```

网格触发逻辑（`_walk` 的 §6 分支）**不动**--只换执行侧的回补判定。这是本方案工程量小的关键：策略层照常发"做T买回"信号，引擎层决定接不接。

### 4.3 底仓消耗与补充

纪律化后部分"减仓"不再回补，底仓会被缓慢侵蚀：

* 到期未回补的量超过原底仓 50% 时（连续多次卖飞），下一趋势层开仓信号自然补足（引擎 max\_holdings 机制放行）

* 极端情况（底仓耗尽）:该票退化为纯趋势进出，T 层自动失效--**结构上是"趋势为主、T 为辅"的正确退化方向**

### 4.4 L2 验收

* 合成数据单测：回补限价拒绝、到期作废、部分回补三种路径

* 三案例复跑：配对 t\_pnl 期望值应 > L1 版本（右尾归零的收益）

* 敞口中位数从 23h -> <8h；跨日占比从 85% -> <40%

## 5. L3 对照层：四机制竞争实验（复用实验矩阵，1 天）

把"哪种 T 机制最好"变成可跑的对照实验，而非争论：

| 机制              | 说明                                                                                 | 参数量 |
| --------------- | ---------------------------------------------------------------------------------- | --- |
| **A 修好的网格**（L1） | 现机制 + 双止损                                                                          | 2   |
| **B 回补纪律**（L2）  | 限价回补 + 到期作废                                                                        | 2   |
| **C 无 T**       | max\_t\_times=0 基线                                                                 | 0   |
| **D 时点规律 T**    | 每日 09:35 卖 1/4 底仓 / 14:50 买回（吃 A 股开盘冲高+尾盘低位规律，你池子的日内结构实证：上午σ3.26% vs 下午1.81%、隔夜为负） | 0   |

* 复用 TREN\_T\_COMPARISON 的实验编排/矩阵表/归因框架（`t_mode` 参数替代 `trend_clock` 维度，或作为第二因子叠加 2×2→2×4）

* **D 的价值定位是"零参数基线"**：若 D 期望值 ≥ A/B，说明这个池子上"无脑时点"胜过"智能网格"--本身就是重要证伪

* 归因口径统一用 L1.2 的新报表（配对口径），四机制直接可比

## 8. 风险与决策点

1. **L1 后期望值可能仍为负**（预估 -1%\~+1% 区间的不确定性）--这正是 Phase 1 的验收目标：用数据决定是否继续 L2，而非预设
2. **L2 的底仓侵蚀**：连续卖飞后底仓减半才触发补充，期间 T 收益基数变小--属设计意图（趋势优先），但需在报告的 reason 中可见（"底仓不足，等待趋势信号补充"）
3. **D 的规律漂移**：时点规律是统计规律非物理定律，实验结论仅对该池该时段有效（与 TREN\_T 的幸存者偏差警示同源）
4. **报表口径切换的用户冲击**：t\_pnl 数字会"突然变差"（从美化口径到诚实口径）--前端迁移提示 + 文档说明，避免误以为策略退化
5. **不做的事**：不实现 VCP 式日内突破 T（方案 C，复杂度高且假突破双向挨打）；不引入 ML 预测日内方向（与项目"可审计优先"哲学冲突）
