## 1. 系统定位与边界

| 维度 | 内容 |
|---|---|
| 输入 | 实时 5 分钟行情（多源）、每日日线（现有 data_update 链路）、用户手动回填的成交记录 |
| 输出 | 开仓/加仓/减仓/止损/清仓/做T 信号推送（理由 + 建议金额 + 参考价） |
| 决策 | **人**。系统只产信号、记账、对账 |
| 策略 | momentum_t / momentum_slot（与回测同一套引擎代码，单一事实来源） |

**为什么半自动**：回测引擎到自动交易之间缺整层执行基础设施（行情推送/下单通道/成交回报/对账恢复）。半自动模式跳过其中 80% 的工程量，先回答三个回测永远给不出答案的问题：实时信号质量、实际滑点、执行纪律。

## 2. 产品功能与界面设计（用户视角）

### 2.1 页面总览（实际落地：单页工作台）

> v1.2 修正：设计稿的五页面在实际落地中收敛为**单页工作台**（LiveSignals.tsx）——
> 五个设计页面的能力全部保留，按使用频率折叠为页面区块，信息密度优先。

| 区块（自上而下） | 一句话定位 | 使用频率 |
|---|---|---|
| **概览四卡** | gate 状态/虚拟持仓/飞书/数据滞后 | 每日扫一眼 |
| **每日信号流程** | 盘前编排/盘中轮询/盘后落库三按钮 + 自动调度开关 + 任务进度条 | 每日 3 次 |
| **盘中信号机** | 重点票实时状态（持仓/状态机/游标），池内候补折叠 | 盘中持续 |
| **信号列表** | 信号流水 + 回填/忽略操作（回填弹窗预填价格/股数/费用自动） | 盘中/收盘 |
| **虚拟持仓** | 现价/市值/浮盈（红涨绿跌）+ 对账校准（以券商为准重建） | 每日核对 |
| **折叠区** | 池子成员卡片流 / 流程参数配置（含交易成本费率）/ 滑点统计 / 影子运行 / M4 就绪 | 按需 |

信息推送双轨：**飞书消息（主，盘中不在电脑前也能收）** + 网页信号流实时刷新（WebSocket，复用现有 `/ws/tasks` 通道模式）。

### 2.2 信号流页（主界面）

每条信号一张卡片：

```
┌─────────────────────────────────────────────┐
│ [开仓·满配] 600339 中油工程      09:35:02    │
│ 理由：加速启动(金叉+站上快均线+入榜+斜率向上)  │
│ 建议金额：280,000 元（9.3%）  参考价：3.253   │
│ 池级：正常(0.62)  段：S3  T+1：明日可卖       │
│ 状态：● 待执行          [回填成交] [忽略]     │
└─────────────────────────────────────────────┘
```

- Tag 颜色与回测交易明细一致（开仓红/止损绿/做T紫/清仓灰），扫一眼知类型
- **状态流转**：`待执行 → 已成交（回填后）｜已忽略｜已过期（默认 30 分钟未回填且现价偏离参考价 > 1.5% 自动置灰）`
- 过滤器：类型 / 代码 / 状态；当日信号置顶，历史折叠
- 止损/清仓类信号**强提醒**（飞书加急 + 网页顶部横幅），开仓类普通提醒

### 2.3 持仓与对账页

- **虚拟持仓表**：代码/名称/数量/成本价/现价/浮盈/持仓天数/`T+1 可卖`标记/所属信号组——T+1 不可卖的行置灰
- **每日对账卡**（15:30 推送）：系统持仓 vs 券商持仓两列对照，差异行红色高亮，`[以券商为准校准]` 一键按钮（回填差异原因备注）
- **月度出金卡**：当月已提 / 目标 20,000 / 缺口挂账，进度条展示（数据来自修复后的出金链路）

### 2.4 成交回填

- **主路径**：信号卡片 `[回填成交]` → 弹窗三字段（成交价/数量/费用），**默认预填信号参考价与建议数量**，改实际值即可（< 10 秒）
- 未成交：点 `[忽略]` 选原因（价格偏离 / 手动放弃 / 已在其他渠道处理）
- 批量补录（M2 后期）：粘贴券商成交单文本自动解析

### 2.5 设置页

- 推送：飞书 webhook 地址 + `[发送测试]`
- 行情源：主备顺序拖拽（mootdx/新浪/腾讯/东财）、各源启用开关
- 策略：`t_mode`（做T机制，默认 off）/ 池子配置（universe_auto 参数组）/ `pool_gate_enter_th`（gate 触发阈值）
- 安全：数据完整性守卫开关、断流熔断阈值（默认 10 分钟）、信号过期时长

### 2.6 每日操作 SOP（用户视角，全程 < 5 分钟）

| 时点 | 系统 | 你 |
|---|---|---|
| 08:30 | 自动推送今日池子/建仓名单/退出条件 | 无需操作，扫一眼 |
| 盘中 | 推送信号（飞书+网页） | 券商 App 下单 → 回系统点 `[回填成交]` 填实际价（30 秒） |
| 15:30 | 推送对账卡 + 当日分钟线落库 | 核对差异 → `[以券商为准校准]`（如有） |
| 月末 | 出金自动记账 | 核对月度出金卡 |

## 4. 行情源（2026-09-02/03 全部实测定稿）

### 4.1 源清单与角色

| 角色 | 源 | 延迟 | 复权 | volume 单位 | 备注 |
|---|---|---|---|---|---|
| **主源** | mootdx（通达信 TCP 7709） | 0.26~0.31s | 不复权 | 股 ✓ | `sources.py` 已集成 `get_minute5`；历史至 2015；含 amount；**TCP 协议免疫 DNS/代理/HTTP 风控** |
| 备源 1 | 新浪 `CN_MarketData.getKLineData`（scale=5） | 0.36s | 不复权 | 股 ✓ | 滚动窗口约一个月；需 UA+Referer |
| 备源 2 | 腾讯 `proxy.finance.qq.com/ifzqgtimg/.../mkline` | 0.25s | 不复权 | **手（×100）** | 老域名 `web.ifzq.gtimg.cn` 已下线，勿再用 |
| 校验 | `qt.gtimg.cn/q=` 实时报价 | 0.05s | 实时价 | 股 ✓ | 五档盘口；最快，盘中交叉校验用 |
| 预留 | 东财 `push2his`（**http** 协议，fqt=1 前复权） | 0.1s | **可复权** | 股 | 本机网络下 https/直连均被 WAF 掐；换网络环境自动可用 |

### 4.2 单位陷阱（多源校验前必须统一）

同一根 bar（600339 2026-09-02 15:00）成交量：新浪 `3,192,600`（股）＝ 腾讯 `31,926`（**手**）＝ mootdx `3,192,600`（股）。**所有源统一换算为股后再做任何计算/校验。**

### 4.3 冗余与校验设计（v1.2：升级双源同刻复核）

- **自动切换**：主源对同一 bar 拉取失败 → 自动切下一源（新浪备）；全部失败返回 None
- **两级校验**（v1.2 实测迭代）：
  1. 快照级：最新完成 bar 收盘 vs qt 实时价偏离 > 1% → **触发双源同刻复核**
  2. 同刻级（方案 A）：新浪拉**同一根 bar** 对比收盘（容差 0.5%）——一致 = 真实急拉
     **放行**（notes 记录）；不一致/无数据/异常 = 坏数据暂停该票（游标不推进）
     ——快照与 bar 天然存在 0~5 分钟时差，急拉票会真实波动超 1%，同刻复核消除误伤
     （2026-09-03 宗申动力尾盘急拉实测：14:40 bar 收 16.42 vs 3 分钟后实时 17.14，
     复核一致放行 ✓）
- **代理环境教训**（实测记录）：本机系统代理对部分 https 域名 CONNECT 隧道有干扰（东财/腾讯曾全挂），Clash `fake-ip` 模式会劫持 DNS。行情客户端必须：`trust_env` 可配置、支持禁代理直连、TCP 主源优先。Clash 侧已加 `fake-ip-filter`（eastmoney/gtimg/sina 走真实解析）与 `DOMAIN-SUFFIX → DIRECT` 规则
- **除权日过滤**：三个 K 线源均不复权。qt 昨收 vs 日线库 as_of 收盘不一致 → 该票**只发提示、不发交易信号**——除权跳空会误触止损线与做T网格

### 4.4 "完成 bar"语义

盘中最后一根 bar 是未完成 bar。**信号只由完成 bar 触发**（bar 结束时刻 +5 分钟判定），进行中 bar 仅用于展示——避免同一根 bar 内信号抖动。

## 5. 运行节奏

### 5. 运行节奏（v1.2：已落地自动调度）

**每日自动调度已实现**（`live/scheduler.py`，后端启动即拉起，`auto_schedule` 可关）：
- 盘前窗口 08:25~11:30：自动提交盘前编排任务（含日线增量更新）
- 盘后窗口 15:25~23:59：自动提交盘后流程
- 仅交易日（trade_calendar）；当日幂等（手动/自动互斥——手动跑过当天不再自动）；
  开机晚自动补跑；提交失败下个 tick 重试

### 盘前（08:30，交易日自动触发 ✓ 已实现）

1. 日线增量更新（现有 data_update 链路）+ 完整性守卫校验
2. 重算全池 T-1 日线特征（momentum_core，T-1 对齐与回测同口径）
3. `universe_auto` 判定：全空仓满 `auto_idle_days`（空仓触发天数）→ `select_top`（含 `rank_key` 排序键、候选域）重选池子
4. `pool_gate` 池级健康度判定（滞回状态机延续昨日状态）
5. 推送：今日池子 / 基准日 / gate 状态 / 昨日到期做T债务

### 盘中（9:30~15:00）

每根完成 bar → 步进状态机 → 信号判定（优先级与回测一致：硬止损 > 衰退退出 > 开仓 > 升级 > 金字塔加仓 > 做T）→ 推送。风控前置检查（`buy_budget`、槽位、`max_intraday_trades` 日内T次数上限、T+1 提示）。

### 盘后（15:30）

1. 当日分钟线落库（minute5 增量，多源比对后取官方口径）
2. 状态机状态落库（§6）
3. 净值快照 / 月末出金结算（复用 `_simulate` 的 `month_settle` 语义：不吃本金、缺口挂账）
4. 做T债务到期处理（`t_debt_max_days` 超时转减仓，与回测同规则）

## 6. 状态持久化设计

回测里状态机活在内存；实盘必须每日落库、次日恢复。最小字段集：

| 表 | 字段 | 对应回测变量 |
|---|---|---|
| `sig_strategy_state` | code, opened, full, adds_done, last_add_idx, last_exit_idx, exit_stage, high_since_open, ref, t_count, score_peak, day | `_walk` 状态机 |
| `sig_t_debt` | code, sold, bought, sell_amt, buy_amt, open_day, deadline_day | `t_state`（做T债务跨日保留） |
| `sig_withdraw` | month, total, t_profit, topup, shortfall, recover, log_json | `w_state`（月度出金） |
| `sig_position` | code, volume, cost_price, group_id, open_day | 虚拟持仓（§7） |
| `sig_signal_log` | ts, code, type, side, reason, suggest_amount, ref_price, source | 信号流水（审计/复盘） |
| `sig_fills` | signal_ts, code, side, fill_price, fill_volume, fill_time, fee | 成交回填（§7） |

恢复语义：次日盘前按最新快照重建状态机；**恢复后首日只允许恢复性信号**（止损/清仓/继续持有），开仓类信号需人工确认一次（防恢复错位）。

## 7. 信号协议（飞书/webhook）

```
【momentum_slot·信号】
类型：开仓（满配）
标的：600339 中油工程 @ 参考价 3.253
理由：加速启动(金叉+站上快均线+入榜+斜率向上)
建议金额：280,000 元（总资产 9.3%，base_pct 区间内）
池级：正常（健康度 0.62）｜段：S3（基准日 2026-09-02）
备注：T+1，明日方可卖出；除权检查通过
```

- 建议金额 = `budget_pct × 虚拟权益`（经 `buy_budget` 同口径约束）
- 每条信号落 `sig_signal_log`；同一 bar 同票同类型信号去重
- 做T信号独立分组推送（可配置关闭——起步建议 `t_mode=off`）

## 8. 虚拟持仓与成交回填（v1.2：状态机联动 + 手续费口径）

- 系统维护虚拟持仓（`sig_position`：数量/摊薄成本/开仓日/**现价快照 last_price/last_ts**），
  信号建议金额基于虚拟权益
- 用户手动成交后**回填实际值**（成交价/量/费）：回填弹窗预填参考价与参考股数；
  **手续费留空自动计算**——复用回测 `Broker.buy_fee/sell_fee`（佣金万0.5最低5元+
  印花税万5卖出+经手/证管/过户双边，费率在流程参数「交易成本」可改）
- **买入费用摊入持仓成本价**（对齐券商摊薄成本口径）；卖出费用计入现金/权益
- **回填联动状态机**（v1.2 堵源头）：买入建仓 -> 状态机 opened/full 置位；
  清仓 -> 复位——否则盘中衰退退出/做T/加仓信号对"真实持仓"失明
- **对账校准**：以券商实际持仓为准**全量重建**虚拟持仓（可编辑表单，预填当前持仓，
  支持空仓校准+二次确认）；只改账本不动信号流水
- **每日收盘对账**：盘后推送对账卡（含每票现价/浮盈），差异人工校准
- 实际成交价 vs 信号参考价 → **滑点流水**（`sig_fills`），月度汇总反哺回测滑点模型

## 11. 已知边界（诚实清单）

- 基准对比用**价格指数**（不含股息 ~2%/年），超额略高估
- 成分表无历史快照：只影响**回测校准**，信号机实时成分无此问题
- 回测滑点模型偏乐观（线性参与率）→ M3 的滑点流水是最终校准依据
- 做T信号（5 分钟网格）人工执行延迟会显著吃掉收益 → `t_mode=off` 起步，验证主逻辑后再议
- 参数校准基于 2024-2026 单一市场周期，未经历长熊检验 → 小资金灰度是硬要求
- **fresh 排序键结构性换手**：新鲜票动量分未展开，"建仓次日衰退退出"是高频事件
  （高换手换快速纠错，试仓 10% 限损）——2026-09-03 688027 实测案例；
  口径实验（v1.2）：建池改按策略分排序（追强）在 4 个分段验证中全面占优
  （含震荡段回撤减半），但单一市场周期样本，采纳需谨慎
- **自动调度依赖后端进程存活**：电脑关机/后端未启动则当日不触发（窗口内补跑仅限
  进程活着的情况）→ 无服务器部署前，开机后手动确认盘前已跑
- **回撤熔断的峰值基于虚拟权益**：对账校准大幅改账会导致权益跳变（峰值仍在），
  校准后如需重新计量，清空重来或手动调 sig_meta.live_equity_peak
