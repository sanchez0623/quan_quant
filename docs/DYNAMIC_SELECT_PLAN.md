## 1. 产品愿景：一条完整的三层数据流

融合后的产品故事（也是系统的终极形态）：

```
┌─ 第一层：池子从哪来（UNIVERSE_PICKER，已有方案）────────────┐
│  申万三级行业 / 沪深300·中证500成分 / 板块 / 随机抽样(seed)     │
│  产出：候选池（10 只 ~ 500 只，含 universe_meta 溯源）          │
├─ 第二层：谁能入场（本方案核心：动态选股）──────────────────┤
│  每日收盘后对全池横截面评估：                                   │
│    排名门槛（top_n 或 RPS 分位）+ 行业限配（防抱团）            │
│    + 确认条件计数（金叉/斜率/突破，满足 entry_need 个）          │
│  引擎在 持仓 < max_holdings 时自动补入命中票（现有能力）        │
│  产出：开仓信号（谁、何时、试仓还是满配）                        │
├─ 第三层：怎么持有（momentum_t 现有能力，不动）──────────────┤
│  试仓→满配升级 / 金字塔加仓 / 过热减仓 / 双确认清仓 / ATR网格做T │
└──────────────────────────────────────────────────────────┘
```

**产品价值主张**：小资金在 5300 只全 A 里靠系统每日动态选出中大盘强势票，趋势吃主升浪、网格做T降成本--选股、持仓、增强三层各司其职。

**select\_trend 原型被吸收的部分**（对照源文件）：

| select\_trend 的设计               | 融入方式                                     |
| ------------------------------- | ---------------------------------------- |
| 三条件计数（金叉/突破/RPS，满足≥entry\_need） | §3.2 入场确认条件模块化                           |
| RPS 横截面前 rps\_top 分位            | §3.3 排名模式 rps\_quantile                  |
| 候选池数百只 + max\_holdings 自动补入     | §3.1 大池产品分层（引擎能力已具备）                     |
| 突破新高作入场条件                       | §3.2 可选条件 breakout                       |
| 跌破慢线清仓                          | **不吸收**--momentum\_t 的双确认清仓（死叉+破线）更保守，保留 |
| 独立策略壳                           | **删除** select\_trend.py 及其注册             |

## 3. 产品设计（四项核心）

### 3.1 产品分层：小池精作 / 大池粗筛（性能决定）

分钟级逐 bar Python 循环是硬约束：500 只池 × 157 交易日 ≈ 380 万 bar，单次回测估 30-60 分钟。据此定义两档产品形态：

| 形态       | 池子规模      | 周期      | 选股 | 趋势 | 做T            | 适用                   |
| -------- | --------- | ------- | -- | -- | ------------- | -------------------- |
| **小池精作** | ≤50 只     | minute5 | ✅  | ✅  | ✅ 全功能         | 现状增强：手工/行业精选池+做T     |
| **大池粗筛** | 50\~500 只 | daily   | ✅  | ✅  | ❌ 自动关闭（无分钟数据） | 动态选股主战场：全市场选股，持仓管理为主 |

* 大池+做T（minute5 全池）标注性能红线，**Phase 2 优化项**：日线预筛+分钟激活两阶段（日线层算排名/条件确定"激活票集合"，分钟层只对激活票跑 T 网格；需重构 prepare 数据流，暂不做）

* 前端在选池后按池子大小提示推荐形态（>50 只且选 minute5 时 Warning："大池+分钟线预计 X 分钟，建议日线模式"）

* E 格（period=daily）即大池粗筛的运行载体，**无需新开发**

### 3.2 入场确认条件模块化（entry\_need 机制，吸收 select\_trend 核心）

**分层语义**：必须条件（资格）→ 计数条件（强度）。

```
必须（不可配）：above = close > ma_slow（站上慢线，趋势策略基本盘）
排名门槛（§3.3）：top_n 命中 或 rps 分位命中（决定"有没有资格被考虑"）
计数池（可配）：macd(金叉) / slope(斜率) / breakout(突破N日新高)
试仓：满足 entry_need_min 个计数条件
满配：满足 entry_need_max 个计数条件（试仓后升级逻辑不变）
```

参数：

```python
{"key": "entry_conds", "label": "入场确认条件", "type": "list",
 "choices": ["macd", "slope", "breakout"], "default": ["macd", "slope"]},
{"key": "entry_need_min", "type": "int", "default": 1, "min": 1, "max": 3,
 "description": "试仓需满足的确认条件数"},
{"key": "entry_need_max", "type": "int", "default": 2, "min": 1, "max": 3,
 "description": "满配需满足的确认条件数（须 ≥ entry_need_min）"},
```

* breakout 复用现有 `add_breakout_n` 窗口计算（现只用于加仓，同时进计数池，一列两用）

* 满配的"试仓升级"分支（`_walk` L357）改为按 entry\_need\_max 判定 confirmed

**行为变化说明（有意的产品演化）**：默认参数（conds=\[macd,slope], min=1, max=2）下，试仓条件从旧版"必须金叉"变为"金叉或斜率任一"（slope-only 也可试仓，但 max=2 仍需两项才满配）。这是给用户条件组合自由付出的最小语义代价；验收用"默认参数信号差异报告"而非严格等价（§8）。

### 3.3 排名模式：top\_n → rps\_quantile（大池语义）

top\_n 是**绝对数量**（前 5 只），池子从 10 只扩到 500 只语义剧变（门槛从 50% 收紧到 1%）。大池需要**相对比例**门槛：

```python
{"key": "rank_mode", "type": "categorical", "choices": ["top_n", "rps_quantile"],
 "default": "top_n",
 "description": "排名门槛模式：top_n=绝对数量（小池）；rps_quantile=横截面分位（大池）"},
{"key": "rps_n", "type": "int", "default": 20, "min": 5, "max": 60, "unit": "日",
 "description": "RPS 相对强度窗口（rps_quantile 模式）"},
{"key": "rps_top", "type": "float", "default": 0.1, "min": 0.01, "max": 0.5,
 "description": "RPS 需处于横截面前 rps_top 分位（0.1=前10%，500只池≈50只候选）"},
```

* rps\_quantile 模式：每票算 `rps = close/close.shift(rps_n)-1`，逐日横截面分位数阈值（select\_trend 原型 L86-96 的实现直接移植），命中日进 top\_days（T-1 语义不变）

* **分数仍用现有多周期风险调整 score**（20/60/120 日混合，比 select\_trend 单一窗口更稳健）--rps 只换"门槛的形状"（分位 vs 排名），不换分数本身

* 大池推荐配置：rank\_mode=rps\_quantile, rps\_top=0.1, max\_holdings=5\~10, top\_n 失效（模式互斥）

### 3.4 行业限配（防抱团，依赖 UNIVERSE\_PICKER 数据）

三案例实证盈利集中于 2 只票（top\_n 押注结构）。加行业维度截断：

```python
{"key": "max_per_industry", "type": "int", "default": 0, "min": 0, "max": 10,
 "description": "每个申万一级行业最多入选只数（0=不限制；依赖行业数据）"},
```

* 实现点：`_rank_days` 每日排名后 join `stock_industry.parquet`（sw\_l1），按行业分组截断再生成 top\_days

* 行业数据缺失的票归"未知"组，未知组同受限额（防数据缺失成为抱团漏洞）

* max\_per\_industry=0 或行业表不存在 -> 完全跳过（零依赖，向后兼容）

* **本参数是 UNIVERSE\_PICKER §1.2 行业限配的落地**，排在数据管道之后实现

## 10. 风险与决策记录

1. **默认语义微调**（slope-only 试仓）：有意的产品演化，T1 差异报告兜底；若不可接受，回退方案为 entry\_conds 强制含 macd 时 min 语义=旧版（校验规则而非硬编码）
2. **entry\_need\_max < entry\_need\_min** 的非法组合：参数校验拦截（前端表单 + validate 双层）
3. **rps 分位在票数极少的池**（<10 只）：分位数噪声大，前端提示小池用 top\_n 模式
4. **行业限配的未知组**：缺行业数据的票归未知组同受限额，防数据缺失成为抱团通道
5. **大池分钟性能**：Phase 5 前不做承诺；产品文档与大池提示明确引导 daily 模式
6. **寻优参数膨胀**：新增 7 参数中 4 个适合进寻优空间（entry\_need\_min/max、rps\_top、max\_per\_industry），遵循 OPTIMIZE\_AND\_AI\_PLAN 的分层原则归入"趋势层/选股组"
